# P5 fine-tuned model evaluation

**Status:** awaiting Kaggle inference JSONL. No model metrics are available yet.

## Setup and reproducibility

- Repository commit used to export the prompts: `9792aad` (working tree contained P5 harness changes).
- Dataset: `corpus/dev/`, all 32 case IDs (8 per class). `benchmark/` and `corpus/test/` are forbidden and were not used.
- Prompt: `p5-v1`, generated by `patcher.prompts.build_prompts()`; all three models must receive the exported identical system/user strings.
- Generation: greedy decoding (`do_sample=false`), seed `42`, `max_new_tokens=2048`, context limit `8192`. Greedy GPU inference is not guaranteed bitwise deterministic across hardware and library versions.
- Base model: `Qwen/Qwen2.5-Coder-7B-Instruct`; revision `c03e6d358207e414f1eca0bb1891e29f1db0e242` is an **approximation** from the latest commit shown in the Hugging Face history before 2026-11-20, not the training revision. It must match the Kaggle inference manifest.
- Quantization: the rank32 training log confirms 4-bit NF4; the notebook code below explicitly sets the two remaining NF4 parameters.
- Updated rank32 notebook evidence (scriptVersionId `371928046`) explicitly sets `load_in_4bit=True`, quant type `nf4`, compute dtype `float16`, double quant `True`, model `dtype=torch.float16`, and `device_map={"": 0}`. The notebook runner now reproduces those values and uses GPU 0 only, without multi-GPU sharding.
- Qlora `run_config.json`, `README.md`, `training_report.md`, and `adapter_config.json` confirm base model, rank 16, alpha 32, dropout 0.05, the seven target modules, training data commit/hash, and package versions. They do not record NF4 compute dtype, double quant, model dtype, or device map. For A those four load settings are labeled **assumed identical** because the shared cell is reported as shared but qlora ran in an earlier notebook version. B's settings are **explicit in the rank32 training notebook code**.
- Rank32 training log reports Transformers 5.20.2, PEFT 0.21.2, TRL 1.18.0, bitsandbytes 0.50.2, Accelerate 1.15.0, Datasets 4.8.5, and PyTorch 2.11.0+cu130. This is rank32 provenance, not a claim about qlora unless its own artifacts confirm it.
- Conditional library defaults: if the actual training `BitsAndBytesConfig` omits `bnb_4bit_compute_dtype`, Transformers 5.20.2 leaves the argument `None` and resolves it to `torch.float32`; if it omits `bnb_4bit_use_double_quant`, its constructor default is `False`. These are verified in the versioned [Transformers 5.20.2 source](https://github.com/huggingface/transformers/blob/v5.20.2/src/transformers/utils/quantization_config.py#L405-L435). Do not treat them as verified training settings until the actual notebook block confirms those arguments were omitted.
- Adapters: A `qlora` (rank 16) and B `rank32` (rank 32); they differ in alpha as well as rank, so this is not a rank-only comparison.
- Docker image: `sha256:d8f383761b89b139aae56746d82011abcf84f72bc3c1176c368336c22802ddf4`.
- Model runs: baseline without adapter, A with adapter, B with adapter; each must have the same 32 prompts and matching tokenized input IDs.
- Procedure: Kaggle HF/PEFT inference writes raw JSONL; `model-compare/replay.py` validates provenance, converts function responses into unified diffs, then uses the unchanged P1 evaluator and Docker checks. This converter is a documented methodological extension of P1, which originally scored raw unified diffs.
- Calibration: DEV has no gold `repair.c` functions. Calibration proves the converter and patch application only; the real functional, exploit, and scanner checks are performed by P1 during replay.

## Caveats

- This is a small development set: only 32 cases, 8 per vulnerability class; no statistical significance claims will be made.
- A is rank 16 and B is rank 32 with a different alpha; observed differences cannot be attributed to rank alone.
- The original training base revision is not recovered; the shared evaluation uses the labeled approximation `c03e6d358207e414f1eca0bb1891e29f1db0e242`. The exact selected revision and tokenizer hashes must match the Kaggle inference manifest.
- Qlora NF4/model-load provenance remains assumed identical rather than verified from its own adapter files; rank32 settings are explicit in its supplied notebook code.
- Greedy decoding and a fixed seed do not ensure bitwise determinism across GPU hardware, CUDA, or package versions.
- There are no gold repaired functions in `corpus/dev/`. The converter unit tests use training gold repairs to prove conversion and P1 patch acceptance only. Docker `calibrate-dev` checks the vulnerable DEV originals' baseline assumptions and exports prompts; it does not evaluate a generated repair.
- The Hugging Face revision in the proposed config is approximate because training logs do not contain a verified model commit. An inference manifest can confirm which revision was evaluated, but cannot establish which revision was used during training.
- Function-to-diff conversion extends P1's original raw unified-diff protocol; raw-format compliance remains separately visible.
